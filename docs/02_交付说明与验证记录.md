## 三、开发过程中定位并修复的真实缺陷

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 报文解析直接抛 `struct.error` | 用 `struct.unpack("!H", 单字节)` 读 TCP 标志；`__slots__` 上写了未声明属性 | 改为直接取字节；删除越界写入 |
| 2 | `tcp.flags.reset==1` 永远匹配 0 条 | Wireshark 别名 `reset` 未映射到 `RST` | 加别名表（RESET→RST、PUSH→PSH） |
| 3 | `ip.addr == x/24` 语义不完整 | 只比较了源地址 | 改为源或目的任一匹配 |
| 4 | 导入 pcap 报 500 | `stop()` 访问未初始化的 `self.engine` | 初始化字段 + `getattr` 防御 |
| 5 | 端口面板一直空数据 | ① `psutil.net_connections()` 每次重算（987 条连接、428ms/次）被前端 4s 轮询叠加，堵死浏览器连接池；② 前端"两个请求合并 try/catch"，任一失败全部丢弃 | 后端加两级缓存（结果 2s / 进程名 30s，实测 428ms → 0ms）；前端拆分为独立 try/catch + 请求超时 + 递归 `setTimeout` |
| 6 | 界面白屏 / 出现旧界面 | 浏览器缓存旧 `index.html`，指向已被清理的旧 assets 文件 | 后端对 HTML 响应加 `Cache-Control: no-cache, no-store` |
| 7 | 汽车协议解析偏移错 | SOME/IP 头按 `HH` 解析（少 2 字节） | 修正为 `!IIIBBBB`（16 字节） |

## 四、使用须知

1. **抓包必须管理员权限**：直接双击 `启动NetEye.bat`（脚本会自行提权）。
2. **完整能力需安装 Npcap**：<https://npcap.com/#download>，安装时勾选 *WinPcap API-compatible Mode*。
   未安装时自动降级为 raw socket（仅本机 IPv4，无混杂模式、抓不到 ARP），界面会显示"无 Npcap"。
3. **AI 需要 Key**：侧栏「AI 分析」→ ⚙ → 填 DeepSeek Key（`https://api.deepseek.com`，模型 `deepseek-chat`），
   点「测试连接」。Key 仅保存在本机 `data/settings.json`，接口返回时打码。
4. **离线分析**：点「导入」加载 pcap，或用 `python server/tools/gen_sample_pcap.py` 生成演示数据。

## 二、本次定位并修复的 4 个真实缺陷

### 1. scapy 在缺失环境变量时直接崩溃（致命）

Git Bash / 计划任务等非登录 shell 下没有 `ProgramFiles`、`SystemRoot`，而 scapy 在
`scapy/arch/windows/__init__.py` 的 `WinProgPath` 里是用 `os.environ["ProgramFiles"]`
**下标方式**读取的，导入即 `KeyError`，导致整个捕获层不可用。

修复：`scapy_engine.ensure_win_env()` 在 import scapy 之前用 `setdefault` 补齐
`SystemDrive / SystemRoot / ProgramFiles / ProgramFiles(x86) / ProgramData / APPDATA /
LOCALAPPDATA`，并把 `%SystemRoot%\System32\Npcap` 显式加入 `PATH`。

### 2. TCP 重传检测把「乱序」误判为重传（严重，影响所有统计）

原实现只维护一个「期望序列号」，凡 `seq < expected` 一律计为重传。而无线网络上乱序
是常态，导致 **WLAN 环境重传率虚高到 8.8%**（ping 网关与外网均 0% 丢包，直接矛盾）。

修复：按 Wireshark TCP Analysis 的判据重写，每个方向维护 `highest_end` 与
`seen[(seq, seg_len)]` 段历史（FIFO 192 条）：

| 条件 | 归类 |
|---|---|
| 该 `(seq, seg_len)` 此前出现过，且间隔 ≥ 0.5ms | 重传 |
| 该 `(seq, seg_len)` 此前出现过，但间隔 < 0.5ms | 驱动重复递交（单列计数，不计重传） |
| 落在已收范围内但从未见过的段 | 乱序 / 部分重叠（**不计入重传率**） |
| `seq > highest_end` 且有缺口 | 丢包缺口（每缺口只报一次） |

序列号比较统一走 `_seq_rel()` 处理 32 位回绕；`tcp_state` 加上 30000 条上限按最近活跃淘汰，
避免长时间抓包内存无界增长。

### 3. TCP Keep-Alive 探测被当成重传（严重，重传率虚高 5 倍）

重放 67618 包真实数据时发现，某些流"重传率"高达 **40–49%**，逐帧核查后真相是：
一条已僵死的连接每 **1.000 秒**发一个 `len=1`、`seq = 末端-1` 的字节，IP ID 每次 +2
——这是标准 **TCP Keep-Alive 探测**，不是丢包。单条这样的流在 223 秒里就贡献 216 次假重传。

修复：识别 `seg_len <= 1 且 seq_end == highest_end` 的段为 Keep-Alive，单列统计（group「保活」），
不参与重传率；同时把重传按间隔分级：

| 间隔 | 分类 | 是否反映链路质量 |
|---|---|---|
| 0.5ms – 200ms | 快速重传 | ✅ |
| 200ms – 5s | 超时重传（RTO） | ✅ |
| > 5s | 陈旧连接重试 | ❌ 半开连接/应用层重试，单独提示 |

### 4. 导出文件名不带扩展名（可用性）

`POST /api/export` 传入 `filename: "live_verify"` 会生成无后缀文件，Wireshark / Excel
无法直接打开。修复：`_ensure_ext()` 在用户未写后缀时自动补齐（pcap/json/csv）。

# v0.1.2 安装链路修复 + 全链路验证（2026-09-19）

## 一、用户反馈
"安装失败，重新测试下，并修复 bug。进行完整链路的测试，确保安装启动运行都没问题。"

## 二、根因分析

### 1. 安装直接失败（根因）
`install.bat` 用 `where python` 判断环境，**本机 `python` 并未加入 Windows PATH**
（Python 只存在于托管目录），于是脚本在第 11 行就打印
`[X] 未找到 python` 并 `exit /b 1` —— 用户看到的就是这个"安装失败"。

复现：把 PATH 收敛到只剩系统目录后执行 `where python`，返回
`INFO: Could not find files for the given pattern(s).`

### 2. 中途踩到的脚本解析坑（已放弃该技术路线）
初版把安装逻辑写成 `tools/install.ps1`，调试中发现：
Windows PowerShell 5.1 读取 **LF 换行**的 .ps1 时，脚本后半段的函数定义会被吞掉
（`ParseFile` 报 0 个语法错误，但 dot-source 后 `Test-Path function:\Find-Npm` 为 False；
文件转成 CRLF 后立刻正常）。同理 `.bat` 用 LF 换行本身也是隐患。
**处置**：改用 Python 实现安装逻辑（可完整自动化测试），并统一所有 `.bat` 为 CRLF。

### 3. 网卡默认选择错误（真实功能缺陷）
`manager.interfaces()` 直接按 Npcap 枚举顺序返回，首位是
"本地连接* 8"（WAN Miniport，无 IP）。默认抓这个口 **永远 0 包**。
**修复**：按 `有 IP > 非链路本地 IP > 私有地址 > 在用 > npcap` 打分排序，
标记 `recommended`，前端优先使用；未指定网卡时后端自动取评分最高者。
修复后列表首位 = `WLAN / 192.168.5.187`。

### 4. 「继续」会清空已抓数据（真实功能缺陷）
`resume()` 直接调用完整的 `start(self.current)`，而 `start()` 会执行
`agg.reset()` + 重建 `records` + `_seq=0`。实测 187 包 → 暂停 → 继续后只剩 16 包。
**修复**：抽出 `_launch()`（只启引擎、不动缓冲区），`start()` = 重置 + `_launch()`，
`resume()` = `_launch()`。实测 187 → 194（暂停）→ 787（继续）→ 803（停止），数据连续。

### 5. 其它修复
- `server/app/main.py`：`@app.on_event("startup")` 改为 `lifespan`，并在退出时停止捕获；
- `has_npcap()` 在 `SystemRoot` 为空字符串时误判"未安装"，改为多候选路径 + 空值兜底；
- 清理误建在 `server/ProgramData/` 下的空目录（环境变量缺失时的相对路径产物）。

## 三、需求 1 整改：Wireshark 级协议树（新增 `server/app/parser/tree.py`，1026 行）

### 1. 数据结构（对齐 Wireshark 的 Packet Details）

```python
LayerNode = {
  "name": "tcp", "title": "Transmission Control Protocol, Src Port: 443, ...",
  "fields": [ {"name": "tcp.flags.syn", "label": "SYN", "value": "1",
               "offset": 34, "size": 1, "desc": "建立连接时同步序列号", "bits": ".... 0001"} ],
  "children": [ LayerNode, ... ]          # 真正的嵌套子树
}
```

- `name` 用 **Wireshark 官方显示过滤器字段名**（`ip.flags.df`、`tcp.options.mss_val`、
  `dns.qry.name`、`tls.handshake.extensions_server_name`…），可直接复制到过滤框使用
- 每个字段带 `offset/size`（精确到字节）→ 前端字段↔字节双向联动
- 每个字段带 `desc`（中文解释）→ 底部说明栏，对应 Wireshark 状态栏
- 位字段带 `bits`（如 `0100 ....`）

### 2. 覆盖范围

| 协议 | 解析内容 |
|---|---|
| Frame | 序号 / 到达时间 / epoch / 帧长 / 捕获长 / **frame.protocols 协议链** |
| Ethernet II | 目的·源 MAC（含 OUI 厂商名）/ 类型 |
| 802.1Q VLAN | PRI / DEI / VLAN ID / 内层类型 |
| ARP | 硬件类型 / 协议类型 / 地址长度 / opcode / 发送方 MAC+IP / 目标 MAC+IP |
| IPv4 | version / IHL / DSCP / ECN / 总长 / ID / **Flags 子节点(RB,DF,MF)** / 分片偏移 / TTL / 协议 / **首部校验和实算 Good/Bad** / 源·目的 |
| IPv6 | version / traffic class / flow label / payload len / next header / hop limit / 地址 |
| ICMP / ICMPv6 | type(+中文名) / code / checksum / ident / seq |
| TCP | 端口 / **stream 索引** / 段长 / seq·ack / 首部长度 / **Flags 值 + 9 个标志位子节点** / 窗口 / 校验和 / 紧急指针 / **Options 逐条展开** |
| TCP Options | EOL / NOP / **MSS** / **Window Scale** / **SACK Permitted** / **SACK 的 left-right edge 区间** / **Timestamps(TSval, TSecr)** |
| **[TCP Analysis Flags]** | 重传（快速/RTO/陈旧）、乱序、序列号缺口、Keep-Alive、零窗口、RST、SYN 扫描 |
| UDP | 源·目的端口 / 长度 / 校验和 |
| DNS | ID / **Flags 逐位子节点(QR,Opcode,AA,TC,RD,RA,Rcode)** / 各区计数 / **Questions 子节点** / **Answer·Authority 逐条资源记录** |
| DNS RR | A / AAAA / CNAME / NS / PTR / MX(优先级+主机) / TXT / SRV(优先级/权重/端口/目标)，**支持名字压缩指针** |
| HTTP | 请求行（方法/URI/版本）或响应行（版本/状态码/短语）+ **逐头部字段（含字节偏移）** |
| TLS | 记录层（content type / version / length）+ **握手（type/version/random/session id）** |
| TLS ClientHello | **加密套件列表（47 套名字映射）** / **全部扩展**：SNI、supported_groups、ec_point_formats、signature_algorithms、supported_versions、ALPN、key_share… |
| TLS ServerHello | 选中加密套件（名字映射） |
| DoIP | version / inverse version / **payload type（14 种类型中文名）** / 负载长 / **DiagnosticMessage 的 SA·TA·UDS 数据** / RoutingActivation |
| SOME/IP | MessageID（服务·方法拆解）/ Length / RequestID（客户端·会话）/ 协议·接口版本 / MessageType / ReturnCode（E_OK…） |
| Data | 载荷长度 + 前 32 字节（**截断显示时 size 同步裁剪，不越界**） |
